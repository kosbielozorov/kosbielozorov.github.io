# 05-ai-usage.md: Working with AI tools (universal)

Rules for **any** AI coding assistant used on this package: Cursor, Claude Code, GitHub Copilot, Playwright planner/generator/healer, or similar. Tool-specific UI differs; **canon and skills do not**.

## Single canon (same for every tool)

Read in order before generating or fixing tests:

1. `../project.md` — paths, fixtures, tags, placement
2. `ai/instructions/02-architecture.md` → **Framework contract**
3. `ai/instructions/03-writing-tests.md` / `06-examples.md` as needed
4. `ai/instructions/01-fundamental-principles.md` as needed — design rationale (KISS/YAGNI/DRY/SOLID) behind the contract, when reasoning about class design or scope tradeoffs
5. `ai/instructions/04-best-practices.md` as needed — debugging/assertion style, DRY helpers, naming conventions not already in the contract

Entry points (same content, different loader):

| Tool                    | Entry                                               |
| ----------------------- | --------------------------------------------------- |
| Cursor / Claude / Codex | `AGENTS.md` (`CLAUDE.md` → `AGENTS.md`)             |
| GitHub Copilot          | `.github/copilot-instructions.md`                   |
| Playwright AI agents    | `.claude/agents/*.md` (loop-dependent) + this index |

## Formulating prompts (all tools)

- **Role:** Senior QA Automation Engineer; TypeScript + Playwright + POM.
- **Atomicity:** one request = one clear task (one POM method, one test, one heal).
- **Constraints:** KISS / YAGNI (`01-fundamental-principles.md`); link the contract instead of pasting it.
- **Attach context** with whatever the tool supports (Cursor `@file`, Copilot `#file`, Claude path/`@`): existing test, POM, and binding/contract when unsure.
- **Tags:** real Testomatio ids via `testomatio-mcp` when creating or syncing tests. Testomatio does **not** provide UI locators — use `playwright-cli` → Playwright MCP for that.

**Good:**

> Create a test for opening the home page. Use `pageManager`, register/extend the POM under `app/ui/pages/`, follow `ai/instructions/06-examples.md`. Obey the Framework contract. Resolve `@T` via Testomatio if missing.

**Bad:**

> Write a test for the cart.

**Ready-to-paste templates:**

- "Create a simple test for [functionality]; resolve its @T via testomatio-mcp, else tag it @unlinked"
- "Add POM locator inline for [description]; use constants only if shared"
- "Create helper for [reusable logic] — only if really repeated" (YAGNI)
- "Refactor [code] according to KISS and YAGNI rules"
- "Check no raw selectors in tests; POM inline vs shared constants in [file]"

## Multi-step work: the handoff

Skill `automate-feature` runs the whole chain with three approval gates. Work on one feature that spans several steps (scenarios → tests and gaps → implementation → run → review) keeps its state in `.work/<feature>/handoff.md`, not in chat: `npm run handoff -- init <feature>`, then `npm run handoff -- check <feature>` after each step. Format, gates and ids: `08-handoff.md`.

**Legacy app without requirements:** skill `characterize-feature` maps the app (`specs/app-map.md`), records what a feature does as observations, pins the zone with temporary `@characterization` scaffolding, and has you triage every observation at Gate 1. Confirmed observations become the spec's Expected lines; then `automate-feature` continues from step 2 on the same handoff (`Flow: characterization`).

## Test first: `npm run gaps`

Write a new test against the members it should have, list the ones you expect to be missing, then run `npm run gaps`. Its list must equal yours; an extra entry is a misspelled existing member — fix the test, do not add the member. Details: skill `playwright-test-creator` → **Test first, then gaps**.

## UI inspection and triage (CLI → MCP)

When the app or a failing step is reachable, **do not** invent DOM from memory or screenshots alone.

**Priority:** (1) `playwright-cli` → (2) Playwright MCP. Details: `07-playwright-ai-agents.md` → **playwright-cli and Playwright MCP**.

After a failed run, build a short bundle with `trace-triage`; then heal per contract **Healing** (POM → shared constants → test).

## Reviewing generated code

Verify against **Framework contract** (`02-architecture.md`) and binding. In Claude Code, run the `test-code-reviewer` subagent (`.claude/agents/test-code-reviewer.md`): it re-runs the gates itself and checks what lint cannot (expected values from the requirement, every scenario **Expected** line asserted, one outcome per test, isolation). To prove that tests would not stay green against a wrong app, run the `adversarial-tester` subagent (opt-in; probes under `.work/review/`, built from `09-mutation-catalog.md`); each of its [REASONED] findings is then judged by an `adversarial-judge` subagent before it reaches you. Use `06-examples.md` for good vs bad patterns. Match existing ESM `import` style. Run the affected test locally (Chrome/chromium unless asked otherwise) before commit.

## Anti-patterns

- Blind commit without `npx playwright test` (or project equivalent) on the changed tests
- Over-engineering (extra base classes / factories) when KISS suffices
- Context-less prompts with no binding/contract/example file
- Invented `@S` / `@T` (use `@unlinked`), `waitForTimeout`, XPath, raw selectors in `*.test.ts`
- "Healing" a test by copying the current app value into an expected value (contract → **Map and oracle**)
- Tool-specific “second policy” that conflicts with `02-architecture.md`

## After changing the Framework contract (maintainers / AI)

When you edit **`02-architecture.md`** (contract) or **`../project.md`** (binding), sync pointers — do **not** paste the full contract into other files:

- [ ] Entry points still link correctly: `AGENTS.md`, `CLAUDE.md`, `.github/copilot-instructions.md`
- [ ] Cursor rule stays thin: `.cursor/rules/qa-playwright-tests.mdc`
- [ ] Playwright agents, if generated into the repo: they do not know the Framework contract — state it in the prompt
- [ ] Skills that mention the rule: especially `playwright-test-creator`, `selector-governance`, `trace-triage`, `testomatio-mcp`, `a11y-playwright-testing`, `playwright-regression-testing`, `grill-me-qa`
- [ ] `07-playwright-ai-agents.md` if CLI→MCP or agent workflow changed
- [ ] `06-examples.md` if a pattern became correct/incorrect
- [ ] Run the gate: `npm run verify` here (typecheck + `lint:contract` + format + `verify:ai`)
- [ ] Scratch `note*.md` files — ignore / do not treat as canon
